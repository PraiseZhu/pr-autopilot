# 原子收敛检查点（review-convergence checkpoint）

> 来源：`xindong/dash` `Skills/git/references/review-convergence.md` §1〜§3。案例背景：
> `makecindy/cindy#844`（2026-07，异步重试/退避改动）37 轮 review、41 个 commit、74 条 P1，
> 事后复盘约一半轮次来自补丁只修对称路径的一半；`#1211` 一个 UI 兜底问题的修复过程中长出
> 一整套锁子系统，25 轮后被整体扔掉才合并。本文档是该方法论在 pr-autopilot `submit-pr` 收口
> 链路里的落地契约，owner 与 lead 已就 D1〜D5 达成共识（各条见下方对应小节）。

## 触发条件（命中即停手，下一个修复 commit 前必须先产出六件套）

三条命中任一即触发：

1. 上一轮修复被指出（或自查发现）漏了对称的另一半——例如 resolve 分支修了、reject 分支
   没修；同步路径修了、迟到/乱序路径没修。
2. 同一语义的判据/guard 在代码里出现第 3 处——连续两次独立加了同一含义的检查，说明判据
   没有归一，继续加第 3 处只是把同一个洞打三个补丁。
3. repair-mode watermark（`SKILL.md`「收敛判据与收口」）计数到第 5 个 candidate 仍出现
   新 family。

## 原子性（D1，硬约束）

六件产出必须**一次性全部完成**才允许提交下一个修复 commit。拆开做——比如这次 commit 只写
不变量、下一次才补测试——**等于没做**：检查点的价值在于修复前先看清全貌，分两次做就退化回
「打一个补丁再看下一条」的老路，触发条件不会因为你做了一半就停止计数。lead 派工时必须把
六件套当成**一个不可拆的整体**（同一 SC 或同一 fix-plan 分组内的强制串行子任务），不得让
worker 先 commit 部分产出。

## 六件套

1. **每个失败族一句话可判定不变量**：把本轮涉及的每个失败族（用下方词典或临场归纳）写成
   一条可判定的不变量。例：「取消后任何迟到的 start 都不得重新激活」。写不出可判定的不变量
   （无法一眼看出某段代码是否满足它）不算完成这一步。
2. **每个状态字段的唯一写入 owner**：为每个状态字段指定唯一写入者与生命周期；发现同一字段
   有多个写入者，先把它们收拢成一个，再继续下一步——多写入者本身就是下一次「漏了对称一半」
   的根因。
3. **事件 × 状态矩阵**（按 D4）：枚举全部事件 × 全部状态，**每格必须写「动作/忽略/拒绝/
   不可能」之一并附一句理由**——空格 = 没想过的路径，禁止留白；判为「不可能」也要写为什么
   不可能，不能用留空表示「这个我已经判断过是 N/A」（留白与「判过是 N/A」在检查点里必须
   看得出区别，否则复核者无法分辨是漏项还是已排除）。
4. **对称路径审计**：resolve / reject / timeout / cancel / close / 乱序 / 重复 / 迟到，
   逐条对照第 3 步的矩阵检查现有代码——这是本检查点的核心，触发条件①「漏了对称的另一半」
   直接对应这一步，也是本检查点存在的主要理由。
5. **判据归一**：同一语义只留一个判据、一条清理路径，所有入口复用；触发条件②里出现的第 3
   处判据在这一步应当被合并掉，而不是任由它继续存在、之后再长出第 4 处。
6. **可鉴别交错测试**：新测试必须能区分「正确修法」与「上一轮那种只修一半的修法」——对旧
   补丁应当红。这不是独立于 `hardening-checklist.md` 第 8 类之外的新判据，是第 8 类反向
   变异判据针对检查点场景的专项应用（见该文件「检查点专项：可鉴别的半修法回归」小节，
   SC-B5）。优先写事件交错序列测试与性质测试，不要逐条 review 评论各配一个孤立回归用例——
   `#844` 累计 +3732 行测试仍压不住组合爆炸，就是后一种写法的下场。

## D2：数字线与六件套的权限边界（与「拒绝数字轮次闸」立场的调和）

`SKILL.md`「收敛判据与收口」一直明确拒绝「跑够 N 轮就停」的数字闸——理由是数字闸切早漏真
问题、切晚继续螺旋。repair-mode watermark（见 `SKILL.md`，第 5 / 第 10 个 candidate）不是
对这个立场的推翻，是**范围收窄后的正交机制**：它**只**切换「这一次修复要不要先做六件套 /
要不要禁止继续同形状打补丁」这一个开关，**绝不**触碰：

- consensus-gate 是否 PASS；
- finding 的 severity 判定；
- 某条 finding 能否走 `[ARCHIVE]`；
- push-guard 是否放行。

这四件事仍然分别由各自的脚本/审查席独立裁决，水位线到第几个 candidate 不改变它们的判据。
即使水位线已经强制了六件套或升级路径，PR 依然可能因为其他原因迟迟不能收口——这正是设计
目的：数字只管「怎么修」，不管「能不能收口」，后者永远是形状判据（连续同族复发/blocker
不减）说话。

## D3：owner 决策范围（升级阶梯「哪些选项需要 owner」的判据来源）

拆 PR、净新增基础设施、用户可见行为/功能范围/发布策略变更——这三类需要 owner 决策；纯
技术升级路径（状态机化、职责上移、缩减实现机制但保留产品语义的降级设计）lead 自主选，
不需要上抛。`SKILL.md`「收敛判据与收口」第 5 条（升级阶梯）与 `hardening-checklist.md`
「新增机制确认门」都以此为界。

**判据不是自称**：技术路径怎么选是 lead 的判断，但要不要缩小用户能看到的范围/能力（划定
范围本身就是功能范围变更）、要不要拆成多个 PR、要不要新增一整类机制——这些属于产品/发布
决策，不能因为「这轮是我在改代码」就默认自己能决定；同样，「我选的是降级设计、声称保留了
产品语义」也不能自动免检——保留没保留看的是改动后用户可见行为是否真的没变，不是选择的
名字叫不叫「降级」。

## 五族失败词典（条件型——命中异步生命周期/重试/取消/并发形状才逐条对照，不对纯同步代码强制）

来源：`review-convergence.md` §1。按不变量归类反馈：同一条被破坏的不变量下的所有表现算
一族，reviewer 换文件、换入口、换措辞不改变族别。只有一条反馈时同样适用——先归因到不变量，
修复覆盖该不变量的全部路径（包括没被点名的位置），不是只修被点名的那一处。

| 失败族 | 典型表现 |
|---|---|
| 结算路径不对称 | resolve 修了 reject 没修；同步路径修了、迟到/乱序路径没修；cancel 前修了、cancel 后没修 |
| 迟到事件重新激活 | 取消/结算之后，迟到的 start / callback / RPC 响应把已终结的生命周期重新拉活 |
| 终态重复 | 终态事件（完成/失败/取消）被发出两次，或被两条独立路径分别发出 |
| 控制信号当数据 | 控制事件（心跳、进度、重试提示）被当成模型输出/业务数据处理 |
| 约束因重试放宽 | 重试、恢复路径绕过了首次路径本该有的权限或前置检查 |

判断「同族复发」的标准：新反馈指向的不变量与已修过的一条相同——这时它不是又一个独立 bug，
是上一轮的修法没有覆盖该不变量的全部路径，继续逐条打补丁只会制造下一轮。

> 本词典**不是**穷尽列表，是异步生命周期类改动里已被真实咬过的五族；命中不属于任一族的新
> 形状仍按第 3 步（事件×状态矩阵）临场归纳，不因词典没列到就跳过对称路径审计（第 4 步）。

## 六件套产出去向

产出贴进 PR body 的 checkpoint marker 段（与 conv-contract 分支引入的 pr-body 锚点机制
衔接——marker 段的脚本化写入/校验归该分支负责，本文档只定义写什么、何时写，不新增脚本）。
产出同时服务三个读者：自己下一步修复时的模型、lead 判断是否收敛的依据、审查席复核 delta
时的判据来源——`review-convergence.md` §2 原文称之为「reviewer 有了明确不变量后反馈会明显
更聚焦，不再每轮换个入口挑一条」。
